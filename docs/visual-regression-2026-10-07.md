# Automated visual regression gate — 7 October 2026

The previous manual screenshot evidence is now complemented by actual committed Playwright screenshot baselines. `npm run test:visual` compares 30 full-page screenshots: home, populated search, Studio dashboard, content editor and homepage editor; dark/light/hidden Aurora; 390×900 and 1440×900 viewports. Each page also has a horizontal overflow assertion. A private local adapter provides three fixed publications and one original local image; no production data is written. Visible lazy images and local fonts must finish loading before capture. The private iframe must report a ready actual desktop viewport.

The separate configuration uses the package-lock-pinned Playwright Chromium headless shell (currently153.0.8010.12/revision1243), UTC/tr-TR, reduced motion and blocked Service Workers. A dedicated windows-2022 job compares the Windows baselines, never updates them, and uploads diffs/traces for failures. Production smoke now depends on both the functional and visual jobs. Cross-platform screenshots are deliberately not compared: rendering differs by environment. See [Playwright visual comparison guidance](https://playwright.dev/docs/test-snapshots).

Only volatile date cells, the development-only Astro toolbar and pointer-position-dependent custom cursor are excluded. UI surfaces, copy, original imagery, controls and focus outlines remain compared. Search explicitly enters keyboard focus before capture. This was necessary because the first comparison run found real autofocus timing differences (28/30 passed); broad thresholds were not increased. Earlier setup also revealed hidden lazy-image waiting and a nonexistent Studio footer wait; these were corrected rather than accepting blank screenshots. An initial fixture setup failed without a response diagnostic; setup now includes the returned error text and is idempotent for test worker restarts.
